# Файловый сервер (Rust + axum)

Веб-сервер для обмена файлами: пользователи загружают файлы через страницу,
любой может скачать их из списка. Хранилище и пароль администратора
настраиваются через защищённую админ-панель; настройки сохраняются в конфиг
и переживают перезапуск сервера. Один бинарник работает на Windows, Linux и macOS.

## Технологии

- **axum** — HTTP-фреймворк (маршруты, multipart-загрузка, извлечение форм/параметров)
- **tokio** — асинхронный рантайм
- **tower-http** (`ServeDir`) — раздача статики
- **serde / toml / toml_edit** — чтение и запись конфигурации
- **tokio-util** — стриминг файлов при скачивании (без загрузки в память)
- **argon2** — хеширование пароля администратора (Argon2id, PHC-формат)
- **rand** — генерация соли и токенов сессий (OsRng)
- **dirs** — кроссплатформенная домашняя директория приложения (Linux/macOS/Windows)

HTML-шаблоны страниц (`static/*.html`, `static/style.css`) вшиваются в бинарник
при компиляции через `include_str!` — рядом с запускаемым файлом никаких
папок быть не должно, бинарник самодостаточен.

## Запуск

```bash
cargo run --release        # сервер на http://0.0.0.0:3000

BIND=127.0.0.1:8080 cargo run            # другой адрес/порт
STORAGE_DIR=/data/files cargo run        # предзадать директорию хранилища
ADMIN_PASSWORD=secret cargo run          # задать пароль админа при первом запуске
FILE_SERVER_CONFIG=/etc/fs.toml cargo run  # свой путь к файлу конфига
```

## Быстрый старт после первого запуска

1. **Первый запуск**: пока пароль администратора не установлен, `/admin`
   открыт без входа (страница «нет доступа» показывается только после его
   установки). Задайте пароль прямо в форме админки (минимум 6 символов) —
   либо заранее через переменную окружения `ADMIN_PASSWORD=... cargo run`
   (удобно в Docker). Пароль в открытом виде не хранится нигде — только
   Argon2id-хеш в конфиге.
2. Там же в `/admin` укажите абсолютный путь к директории для файлов
   (папка создаётся автоматически) и сохраните. Для последующих входов —
   страница `/login`, дальше достаточно одного логина (сессия живёт 8 часов).
3. Пока директория не выбрана, на главной висит заглушка
   «Сервер ещё не настроен — обмен файлами работать не будет»,
   а `/upload` отвечает `503`.

Настройки (директория + хеш пароля) сохраняются в файл конфига и подхватываются
при следующем запуске без переменных окружения.

## Конфигурация

Файл конфига размещается в домашней директории приложения (крейт `dirs`),
поэтому один и тот же бинарник одинаково себя ведёт на разных ОС:

| ОС      | Путь по умолчанию                                  |
|---------|----------------------------------------------------|
| Linux   | `~/.config/file-server/file-server.toml`           |
| macOS   | `~/Library/Application Support/file-server/file-server.toml` |
| Windows | `%APPDATA%\file-server\file-server.toml`           |

- Формат по умолчанию — **TOML** (человекочитаемый, с комментариями);
  поддерживается также **JSON** — формат определяется по содержимому при чтении.
- Переменная `FILE_SERVER_CONFIG` переопределяет путь к файлу конфига.
- Запись атомарная (временный файл + rename), права на файл — `600`.

Пример (`file-server.toml`):

```toml
version = 1
storage_dir = "/data/files"   # пока пусто — сервер «не настроен»

[admin]
password_hash = "$argon2id$v=19$m=19456,t=2,p=1$...$..."
```

## Как это работает

1. **Главная** — `/`: drag-and-drop / выбор файлов (несколько сразу, лимит
   100 МБ на файл), список доступных файлов с кнопками «Скачать».
2. **Скачивание** доступно всем без входа; файлы стримятся с диска.
3. **Админ-панель** — `/admin` (только после входа): выбор директории
   хранилища, смена пароля, сброс настройки. Пользователь без входа видит
   на этих страницах «У вас нет доступа к админ панели» (`403`).
4. **Настройка не выбрана** — главная показывает заглушку, загрузка/скачивание
   возвращают `503`.

## Маршруты

| Метод    | Путь                 | Доступ        | Назначение                                   |
|----------|----------------------|---------------|----------------------------------------------|
| GET      | `/`                  | все           | главная (или заглушка «не настроен»)         |
| POST     | `/upload`            | все           | multipart-загрузка файлов                    |
| GET      | `/download/{name}`   | все           | скачивание файла (стриминг с диска)          |
| GET/POST | `/login`             | все           | страница входа и проверка пароля             |
| GET      | `/logout`            | админ         | выход (отзыв сессии)                         |
| POST     | `/delete/{name}`     | админ         | удаление файла                              |
| GET/POST | `/admin`             | админ*        | настройка директории, смена пароля, сброс    |
| GET      | `/style.css`         | все           | стили (из вшитого в бинарник шаблона)        |

\* До установки пароля `/admin` открыт без входа — это окно первичной настройки.

## Безопасность

- **Пароль администратора** хешируется **Argon2id** (memory-hard KDF,
  OWASP-рекомендация) и хранится в PHC-формате с уникальной солью;
  проверка — constant-time (реализована внутри `password-hash`),
  сам пароль в открытом виде не сохраняется нигде.
- **Сессия админа** — случайный токен (OsRng) в cookie `HttpOnly; SameSite=Lax`
  с TTL 8 часов; logout отзывает токен на сервере.
- **Разграничение доступа**: middleware закрывает `/admin`, `/logout`
  и `/delete` — пользователи без входа получают `403` со страницей
  «У вас нет доступа к админ панели» (кроме окна первичной настройки пароля).
- Имена файлов санитизируются (убираются пути, управляющие символы, `..`);
  скачивание возможно только для файлов внутри настроенной директории
  (path traversal блокируется: `../` → `404`).
- HTML экранируется во всех страницах; совпадающие имена получают суффиксы
  `(1), (2)…`.
- Файл конфига пишется с правами `600` (owner read/write).

> Примечание: файлы хранятся на диске **в открытом виде** и передаются по HTTP
> без шифрования. Для продакшена поставьте сервер за reverse-proxy с TLS
> (nginx/caddy + Let's Encrypt) — тогда трафик будет зашифрован в канале.

## Разработка

```bash
cargo test               # юнит-тесты (auth, config, санитизация имён)

```

Папка `/test-folder` (локальные проверки) исключена через `.gitignore`.
